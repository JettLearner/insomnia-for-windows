# Autopilot — 定时提示词投递

> Insomnia for Windows 1.2.0 · English: [autopilot.md](autopilot.md)
> 相关源码：`shared/autopilot.ts`、`shared/autopilot-ui.ts`、`electron/core/autopilot-*.ts`、`src/routes/Autopilot.tsx`

> **内部功能，不随发布版提供。** 代码保留在仓库中，但托盘入口与面板按钮默认隐藏，调度器也不会启动，
> 只有以 `INSOMNIAZ_AUTOPILOT=1` 启动应用时才会启用。本文档仅供开发使用：README 不再链接它，
> 发布说明也不包含它。

Autopilot 是一个后台常驻的调度器：到点后把一段完整提示词连同附件、模型、思考强度、参数与目标会话，
投递进桌面 AI 聊天应用。目标应用**不需要**处于前台；除非任务里写明，否则 Autopilot 不会替你预选模型或会话。

> **请先读这一段。** 与软叫停的 GUI 兜底不同，Autopilot **没有 dry-run、没有白名单、也没有确认闸门**。
> 任务触发时会真的写入提示词、真的点击发送。第一次对某个目标使用时，请一边看着屏幕一边点 **立即执行**。

## 1. 打开方式

- 主面板底栏的时钟按钮，或
- 托盘右键菜单 → **Autopilot**。

它是一个**可自由缩放的普通原生窗口**（可最小化、最大化、全屏，有任务栏条目），不是托盘弹层。
关闭或最小化只是隐藏，调度器继续运行。关闭设置窗口会自动弹回主控制面板。

## 2. 首次投递前必须做的事

1. **自己先启动目标应用**并登录。Autopilot 不会替你拉起它；找不到窗口会以 `TARGET_NOT_RUNNING` 失败。
2. 让目标窗口**保持可见**（不要最小化）。最小化的窗口会被恢复或推迟，绝不会被盲点。
3. 打开 **模型** 页，对 ZCode / WorkBuddy 点 **同步**，让目录反映你账号真正能用的模型。
   不同步就只有内置种子目录。
4. 建好任务后先用 **立即执行**，全程看完第一次投递。
5. 确认无误后再交给它无人值守运行。

自动化助手 `InsomniaZAuto.exe` 从应用资源里懒启动，**不需要管理员权限**。
以管理员身份运行的目标应用，只有在同样提权的 Insomnia for Windows 下才能被自动化。

## 3. 页签

| 页签 | 内容 |
|---|---|
| **任务** | 所有任务、下次执行时间、上次结果与编辑器 |
| **运行记录** | 最近 60 次运行，含通道、尝试次数与逐步明细（磁盘保留 500 条） |
| **模型** | 合并后的模型目录：供应商、名称、上下文窗口、来源 |
| **会话** | 从目标应用采集到的会话 |
| **附件** | 备份台账：原始路径、备份、大小，以及复原与删除操作 |
| **设置** | 应急通道、隐私保护、调度默认值 |

## 4. 新建任务

编辑器按顺序有六张卡片。

### 名称与目标

`目标应用` 可选 **ZCode**、**WorkBuddy**、**WorkBuddy AI**、**任意窗口**（通用匹配）或
**仅兜底通道**（完全不碰 GUI）。`会话` 可以是**当前**会话、**指定名称**的会话或**新建**会话。
选 **任意窗口** 时，窗口匹配填进程名或标题，支持 `contains` / `equals`；留空则匹配所有 AI 窗口。

### 计划

| 类型 | 字段 | 行为 |
|---|---|---|
| 仅手动 | — | 只在点 **立即执行** 时投递 |
| 单次于 | 日期 + 时间 | 投递一次后任务转为空闲 |
| 每天 | 时间 | 每天该本地时间投递 |
| 每周 | 时间 + 星期几芯片 | 只在选中的星期几投递（周一…周日） |
| 间隔（分钟） | 1…10080 | 按间隔重复 |

**错过执行时**（应用没开、电脑睡眠）可选 `补跑一次`（默认）或 `跳过`，
受设置里的补跑窗口限制（默认 10 分钟，最长 24 小时）。

### 模型

- `名称` 与 `供应商` 是带目录建议的自由文本。留空表示沿用目标应用当前选择。
- **思考强度**是五档环：`关闭 → 低 → 中 → 高 → 最高`。在 ZCode 里用 `Ctrl+T` 逐档切换并回读确认；
  只有读不到标签时才去点滑块。
- `temperature`、`topP`、`maxTokens` 在目标应用暴露这些参数时透传。

当模型因账号无额度而不可用时，Autopilot 会**先刷新模型列表再选下一个候选**，绝不会带着空模型硬发。

### 技能与上下文

自由填写 `mode`，以及工作区、技能、MCP 服务、插件与专家。这些内容会写进给目标应用的提示词上下文；
Autopilot 不校验目标应用是否真的应用了它们。

### 提示词

上限 **200 000 字符**，空提示词无法保存。附件缺失或过大时会自动在提示词后追加说明（见第 5 节）。

### 附件

用文件对话框选择（每个任务最多 **40** 个）。每个附件可开启备份，并有保留策略
（`delete_now` 立即删除、`keep` 保留、`expire` N 天后过期）。从界面添加的附件默认 `backup: true`、
`keep`，但**只有在设置里打开“投递前备份附件”才会真的复制**，该开关默认关闭。

## 5. 附件与“原路径优先”规则

交给目标应用的路径**永远是你的原始路径**，绝不是备份目录。四种情况：

| 原始文件 | 备份 | 行为 |
|---|---|---|
| 存在 | 任意 | 读原文件；开启备份时刷新备份 |
| 被移动 | 任意 | 按**文件名加大小或哈希**搜索，使用找到的路径并记住它 |
| 已丢失 | 有 | **先把备份复原到原目录**，再投递原始路径 |
| 已丢失 | 无 | 跳过，并在提示词后追加 `【附件缺失说明】…` |

复原优先于搜索，因此别处的同名文件不可能顶替你的文件。对已知文件，同名候选只有在大小或
SHA-256（前 64 KiB）吻合时才算命中。原目录不可写时，附件以 `restore_target_unavailable` 跳过，
而不是改从别处投递。

搜索范围：原目录、其父目录、历史已知路径、你配置的搜索根，以及桌面/文档/下载；最深 3 层、
最多 50 000 个条目、3 秒预算。附件缺失或过大**不会让整次运行失败**——追加的说明会写清跳过了什么。

删除备份只限于受管的备份根目录，永不动你的原始文件。

## 6. 模型与会话

目录合并三个来源：内置种子、从目标应用实时同步、手工编辑。

- **ZCode**：模型弹层右列第一行是当前供应商，点它才展开左列供应商列表与 `管理模型`。
  同步会打开模型设置，点击 `添加供应商` 左侧那个**无文字图标**刷新键，再读取列表。
- **WorkBuddy**：MSAA 几乎为空，因此用 `PrintWindow` 截图 + WinRT OCR 识别。
  模型行带 `0.29x` 这样的倍率后缀，程序据此识别模型行。

ZCode 因账号无额度而不显示模型时，刷新发生在**选模型之前**，所以定时任务可以自行恢复。
会话与目录一起保存，程序不会替你新建或重命名会话。

## 7. 运行记录、通道与错误

一次运行会记录 `route`（`zcode`、`workbuddy`、`generic`、`fallback-ollama`、`fallback-api`）、
尝试次数与最多 200 条步骤。任务状态为
`idle · queued · running · sent · failed · skipped · deferred · blocked`。

重试遵循内置错误目录：每个错误码有自己的尝试上限、退避与终态动作
（`fallback` 转兜底、`deferred` 推迟、`next-candidate` 换候选、`continue` 继续、`failed` 失败、
`blocked` 阻塞）。例如：

| 错误码 | 含义 | 处理 |
|---|---|---|
| `TARGET_NOT_RUNNING` | 目标应用没有窗口 | 2 次尝试（5 秒、15 秒）后转兜底 |
| `WINDOW_MINIMIZED` | 窗口被最小化 | 推迟 |
| `MODEL_UNAVAILABLE_NO_QUOTA` | 该账号用不了这个模型 | 刷新、换下一个候选，再转兜底 |
| `RATE_LIMITED` | 被供应商限流 | 4 次尝试（30 秒 → 5 分钟）后转兜底 |
| `SEND_DISABLED` | 发送键一直不可用 | 3 次尝试后转兜底 |
| `SEND_UNCONFIRMED` | 点了两次发送仍无法确认 | 以 `DUPLICATE_RISK` 失败并**阻塞任务** |
| `PROTECTION_DEFERRED` | 保护闸门判定忙碌 | 推迟，任务按住 5 分钟 |
| `SOFT_STOP_INTERCEPT` | 软叫停正在接管桌面 | 推迟 |
| `ATTACHMENT_MISSING` | 附件不可读 | 追加缺失说明后继续 |
| `FALLBACK_NO_KEY` | 开了远程兜底但没存密钥 | 直接失败，不调用付费接口 |

**每次运行最多点两次发送。** 这是刻意的：第三次点击可能把提示词重复发出去。
两次之后仍无法确认，运行失败且任务被阻塞，交给人来看。

## 8. 应急兜底链

只在 GUI 重试耗尽后使用（`仅兜底通道` 则直接使用）：

1. **本机 Ollama** — `POST {base}/api/chat`，默认 `http://127.0.0.1:11434`，
   默认模型 `qwen2.5-coder:7b`。发往这里的请求**永不**带 `Authorization` 头。
2. **OpenAI 兼容端点** — `POST {base}/chat/completions`，默认
   `https://open.bigmodel.cn/api/paas/v4`，默认模型 `glm-5.3-flash`。
   **默认关闭**；只有显式开启远程访问且已保存密钥时才会使用。

每个通道 3 次尝试，二次退避（500 毫秒、2 秒），超时 60 秒。`stream:false`；
temperature/top-p/max-tokens 取自任务。文本附件以 `--- 名称 ---` 块内联，上限 200 000 字节；
**图片只在 Ollama 通道以 base64 内联，在 API 通道会被丢弃**。

兜底得到的回复**不会保存、也不会转发**给目标应用——兜底保证的是你的提示词到达了**某个**模型，
而不是答案出现在你的聊天窗口里。运行记录的通道字段会显示是哪条通道应答的。
密钥用 DPAPI 加密；日志只留状态码。

## 9. 隐私保护闸门

只要存在启用的 GUI 任务，闸门每 5 秒采样一次：

| 判定 | 触发条件 | 效果 |
|---|---|---|
| `capturing` | 软叫停接管桌面，或检测到录屏进程（`obs64`、`obs studio`、`screen rec`、`屏幕录制`、`bandicam`、`camtasia`、`snipping`） | 隐藏 Autopilot 窗口，推迟 GUI 投递 |
| `taken_over` | 检测到远程控制（`todesk`、`sunlogin`、`向日葵`、`teamviewer`、`rustdesk`、`anydesk`、`parsec`、`mstsc`、`remote desktop`、`远程桌面`、`leoworkspace`） | 同上 |
| `hot` | CPU 超过阈值（默认 0.75，可设 0.3…0.99） | 同上 |

匹配方式是“进程名 + 窗口标题”的大小写不敏感子串。忙碌判定解除后仍会**继续推迟 20 秒**，
避免录制过程中自动化闪回。被推迟的运行按住 5 分钟。没有启用的 GUI 任务时，闸门完全不探测。
窗口隐藏期间调度器与引擎照常运行。

## 10. 落盘文件

全部位于 `%APPDATA%\InsomniaZ\autopilot\`：

| 文件 | 内容 |
|---|---|
| `autopilot-jobs.json` | 任务与计划 |
| `autopilot-settings.json` | 调度、兜底与保护设置 |
| `autopilot-runs.json` | 最近 500 次运行 |
| `autopilot-catalog.json` | 模型目录**与**采集到的会话 |
| `autopilot-attachments.json` | 备份台账 |
| `autopilot-secret.json` | DPAPI 加密的兜底 API 密钥 |
| `attachments/<任务>/<附件>/` | 备份副本 |

写入是原子的；损坏的文件会被保留为 `<名称>.corrupt-<时间戳>` 而不是删除。
任务运行中编辑是安全的——改动会自适应实时保存（基准 500 毫秒，负载高时拉长，最长不超过 15 秒），
并在睡眠与关机前 flush。

## 12. 故障排查

| 现象 | 可能原因 | 处理 |
|---|---|---|
| 每次都 `TARGET_NOT_RUNNING` | 应用没开，或窗口在别的虚拟桌面 | 启动它并让窗口保持可见 |
| 任务被阻塞且报 `DUPLICATE_RISK` | 点了两次发送仍无法确认 | 检查目标应用是否有弹窗或发送键改版，再重新启用任务 |
| 到点没动静 | 补跑窗口已过期，或任务是“仅手动” | 检查 **错过执行时** 与补跑窗口 |
| 每周任务在错误的日子触发 | 没选星期几 | 在计划卡片里勾选星期几 |
| 芯片显示“已被接管 / 负载偏高” | 有远程控制工具或 CPU 负载高 | 关掉工具或调高阈值；20 秒冷却后自动恢复投递 |
| `FALLBACK_UNCONFIGURED` | 两条通道都没开 | 开启 Ollama，或开启远程访问并保存密钥 |
| `FALLBACK_NO_KEY` | 开了远程但没密钥 | 在 设置 → 应急通道 里保存密钥 |
| 模型列表为空 | 账号无额度，或从未同步 | 点 **同步**；Autopilot 也会在选模型前自行刷新 |
| 提示词到了但附件没到 | 文件缺失/过大，或复原目标不可写 | 看追加的 `【附件缺失说明】` 与附件页 |

## 13. 已知限制

- **Autopilot 没有 dry-run 与白名单**，它会真的点击。第一次请有人值守地用 **立即执行**。
- **目标应用必须已经在运行**，程序不会替你拉起它。
- **兜底的答案不会回传**到目标应用，且图片在 API 通道会被丢弃。
- **OCR 依赖目标应用当前布局。** 控件位置以窗口相对比例（不是屏幕像素）保存，
  因此非最大化窗口、多显示器与 DPI 变化都能适配；但目标应用改版仍可能破坏识别。
- **纯 Canvas 且无可读文本、无障碍树的界面**无法驱动。
- 针对 ZCode 与 WorkBuddy 的真机投递按版本验证；具体测了什么、没测什么见
  [发布说明](release-notes-v1.2.0.zh-CN.md)。
