## 1. 评审范围与方法

1. **源码通读**：主进程（`electron/`）、渲染层（`src/`）、共享模型（`shared/`）、helper（`resources/helper/InsomniaZHelper.cs`）、构建与打包脚本。

3. **安全审计**：窗口安全选项、CSP、IPC 暴露面、导航与网络守卫、helper 管道与提权边界。
4. **需求对照**：`docs/04-acceptance.md` 的 FR-01…FR-43 矩阵，逐项确认状态与证据。
5. **独立复核**：对高风险链路（合盖恢复、并发、提权）进行代码走查与日志/WMI 交叉验证。

## 2. 架构评审

### 2.1 进程与窗口模型

| 层 | 职责 | 评价 |
|---|---|---|
| Electron 主进程 | 状态机、计时、托盘、窗口、IPC、日志 | 单实例；状态集中于 `Controller`，UI 不持久化业务状态 |
| 渲染层 | 面板 / 设置 / 引导，React 19 | 无 Node 权限；只通过 preload 的 12 个方法通信 |
| helper | 执行状态、合盖策略、F15 活动 | 独立进程、独立线程保持 `SetThreadExecutionState`；崩溃不拖垮 UI |
| Windows | 电源策略、托盘、通知 | 原生托盘菜单承载原 macOS 顶栏交互 |

窗口策略：全部 `skipTaskbar`；面板 `type:'toolbar'`，原生 exStyle `0x80088`（TOOLWINDOW + LAYERED + TOPMOST）；设置/引导为普通无边框窗口；关闭一律“隐藏”，退出只由显式命令触发。符合“纯托盘应用”的定位。

### 2.2 防休眠分层

1. `powerSaveBlocker`：显示常亮用 `prevent-display-sleep`，仅系统不休眠用 `prevent-app-suspension`。
2. helper 线程：`ES_CONTINUOUS | ES_SYSTEM_REQUIRED [| ES_DISPLAY_REQUIRED]`，覆盖主进程短时阻塞。
3. 合盖策略：Power API 写 `LIDACTION=0`，AC/DC 同时写；先备份、再写入、再回读校验；失败自动还原。

三层职责清晰，任一层失效仍有冗余。合盖策略是全局副作用，代码对其采用“显式开关 + 明确错误 + 永不静默恢复”的保守策略，方向正确。

### 2.3 合盖恢复与并发

最终实现包含三个关键机制：

- **写前备份**：helper 在写策略前持久化 `lid-recovery.json`；写入/校验失败调用 `RestoreAfterFailedApply`，避免“策略已改、备份没写”的崩溃窗口。
- **20 秒心跳**：控制器在会话激活且合盖开启时重放 `applyLid`；helper 检测活动方案 GUID 变化并迁移，覆盖用户切换电源方案。
- **lid 操作串行化**：所有会改动合盖状态的 helper RPC 都经过 `withLidLock` promise 队列；心跳、停用、恢复、崩溃恢复不会交叉执行。

这三点是本项目最容易出错的地方，均已在最终代码中闭环（见 F-01～F-03）。

### 2.4 数据与持久化

设置、会话、日志、恢复文件全部位于 `%APPDATA%\InsomniaZ`；写入采用临时文件 + rename 的原子方式；设置清洗对未知键、类型错误、越界值、原型污染键均有处理。没有注册表写入（开机启动使用系统登录项 API），没有云端同步。

## 3. 安全评审

| 面 | 措施 | 结论 |
|---|---|---|
| 渲染隔离 | `contextIsolation:true`、`sandbox:true`、`nodeIntegration:false`、preload 白名单 | 通过 |
| CSP | `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'` | 通过（内联样式为 React 运行时所需，脚本严格） |
| 导航 / 新窗口 | `will-navigate` 阻止、`setWindowOpenHandler` 拒绝 | 通过 |
| 网络 | 主进程 `webRequest` 守卫拦截全部远程请求；无分析 SDK、无自动更新 | 通过（未抓包，静态 + 运行时日志） |
| IPC | 仅接受受信窗口 sender；命令按类型逐字段校验；无任意通道暴露 | 通过 |
| helper 通道 | 随机命名管道 + 32 字节随机 token + 父 PID 监视；非法 token 返回 `UNAUTHORIZED` | 通过（威胁模型见 6.3） |
| 提权 | 仅在用户显式开启合盖保护时请求 UAC；非提权 `applyLid` 返回 `ELEVATION_REQUIRED`，绝不静默写入 | 通过 |
| 外链 | 仅 `apps.apple.com`、`pawandixit.com` 的 https 链接，经系统浏览器打开 | 通过 |
| 生产 DevTools | `devTools: this.isDev`；生产禁用，且窗口隐藏时关闭 DevTools | 通过 |
| 签名 | 未签名 | 已披露（F-14） |

安全基线符合桌面托盘工具的合理标准。没有发现可远程利用的入口；主要残余风险是本地同用户进程与物理电源行为。

## 6. 残余风险与威胁模型

### 6.1 物理与环境

1. **物理合盖**：提权、写入、恢复链路已在真机走通，但未合盖验证任务不中断；未测合盖状态下拔插电源。需在有管理员权限的机器上按验收报告 8.2 执行。
2. **睡眠/休眠恢复**：`resume` 会重放执行状态并重申请合盖，20s 心跳兜底；未做真实睡眠唤醒 E2E。
3. **通知视觉**：开始/结束/低电量/权限失败均有调用点，但是否被专注助手拦截需人工确认。
4. **Windows 11 / OEM 电源方案**：仅在 Win10 19045 平衡方案实测；其他方案走同一 Power API/回退路径，未逐一覆盖。
5. **安装版开机启动**：`setLoginItemSettings` 已实现；便携版按设计不支持；未做注销/重启验证。
6. **多显示器 / 混合 DPI**：面板按光标所在显示器工作区定位；仅在单显示器 150% 下实测。

### 6.2 性能

空闲 CPU 0–0.16%，菜单重建 ≤0.2 次/秒；内存 212.9 MB，未达 160 MB 目标。若必须压到目标，需要移除 GPU 进程或改用原生 Win32 重写，属于超出本次移植范围的结构性取舍。

### 6.3 helper 协议威胁模型

helper 以当前用户身份启动、按需提权；命名管道为随机名，消息必须携带随机 token；helper 监视父 PID，父进程消失即退出并恢复合盖策略。威胁模型假设“同一 Windows 用户下的进程是可信的”：同用户恶意程序若取得 token，理论上可向 helper 发送命令；但 helper 只执行有限的执行状态/合盖命令，且真实合盖写入需要用户已批准的提权 helper。该风险已在评审中接受；后续可用管道 ACL + `GetNamedPipeClientProcessId` 进一步收紧到父进程。

### 6.4 供应链与分发

- Electron/Chromium 版本固定；依赖锁定；构建离线可复现（镜像仅用于 electron-builder 二进制）。
- 未签名，无法证明发布者身份；分发时应同时提供 SHA-256。

## 7. 验证事件与处置（透明记录）

自动化期间，一次会话启动触发了合盖偏好流程：

- 17:13:33 请求提权，17:13:36 UAC 被接受，helper 以 `elevated:true` 连接；
- 17:13:36 写入合盖策略，日志记录原值 `1/1`；
- 17:14:49 父进程退出，helper 恢复 `values=1/1`；
- 17:32 与 17:35 两次 WMI 复核 `LIDACTION` 均为 AC=1、DC=1，`lid-recovery.json` 不存在。

处置：确认无策略/文件残留后，将测试配置恢复为默认（合盖偏好开、失焦隐藏开、会话恢复开），并在后续 UI 自动化中关闭合盖偏好，避免再次触发 UAC。该事件同时提供了提权与写入/恢复链路的真机证据，已写入验收报告 4.2；物理合盖仍未验证。

## 8. 评审结论

- 架构边界清楚，三层防休眠与合盖恢复符合桌面电源工具的最佳实践；高风险副作用均有显式开关、备份、校验与恢复。
- 安全基线达标：渲染隔离、严格 CSP、IPC 校验、导航/网络拦截、helper token 与父 PID 监视；无远程入口。
- 交互覆盖原 macOS 顶栏的主要能力，并按要求迁移到托盘右键；面板、设置、引导的视觉与双语完整。
- 58/58 单测、37/37 冒烟、8/8 首启冒烟零失败；最终产物完成真实点击、退出与进程回收验证；提权写入/恢复已在真机走通并复原。
- 无未关闭 P0/P1；P2/P3 为环境限制或已披露的取舍（物理合盖、通知视觉、Win11、开机启动、安装/卸载、签名、内存）。

**评审判定：通过，可交付。** 交付时必须同时保留本评审、验收报告与产物 SHA-256，并明确“物理合盖仍需真机复验”。
